## 지금 기준 보충

### 버전 문자열

- 단일 소스는 `src/utils.js` 의 `APP_VERSION` 한 줄입니다.
- `build.sh` 가 이 값을 `public/sw.js`(캐시 무효화 키)·`bulk_tally.html` 라벨·README의
  `> **현재 버전** · …` 줄에 자동 동기화합니다. **손으로 여러 곳을 고치지 마십시오.**
- 콘앱(`public/cone.html`)의 `__CONEV` 는 콘앱 자체 버전이라 동기화 대상이 아닙니다.

### 빌드

```bash
npm install
bash build.sh          # npm run build 직접 호출 금지
```

`build.sh` 가 하는 일: 옛 산출물 제거 → vite build → `dist/` 를 루트로 복사(GitHub Pages가 루트를 서빙)
→ 콘앱 카고플랜 번들 생성 → **연막검사**(jsdom으로 실제 렌더) → 번들에 APP_VERSION이 박혔는지 확인.
연막검사가 실패하면 빌드가 실패합니다 — "빌드 성공"만으로 배포하지 않기 위한 장치입니다.

### 배포

**`DEPLOY.md` 가 정본입니다.** 배포는 끝까지 직접 합니다("이제 push 하시면 됩니다" 금지).

### 범용판(TallyUni)에서 달라진 것

- 회사·모항·터미널·소유자 등 테넌트 값은 `src/tenant.js` 단일 소스이며,
  실제 값은 첫 실행 마법사(`src/pages/SetupWizard.jsx`)가 받아 localStorage 2키
  (`gm_fb_cfg_v1`·`gm_tenant_cfg_v1`)와 데이터베이스 `settings` 노드에 저장합니다.
- Firebase 접속 설정은 빌드에 굽지 않습니다(`src/firebase.js` 런타임화). 설정이 없으면 `db=null` 이고
  앱은 마법사 화면만 그립니다.
- 데이터베이스 접근은 익명 인증 뒤에만 일어납니다(`fbAuthReady()`), 규칙은 `auth != null`.

### 메일 수집기(MailPilot) — 0.2에서 POP3를 넣은 이유

- 회사 도메인 메일(후이즈)은 **IMAP을 제공하지 않습니다**(웹메일 호스트 143/993 닫힘, 공식 안내도 POP만).
  공식 안내 값은 `pop.whoisworks.com : 995 (SSL)`, 아이디는 메일주소 전체, 비밀번호는 웹메일 로그인 비밀번호입니다.
- 제품 요구(검수사)는 "아이디·비밀번호만으로 붙는 것"입니다. 앱 비밀번호·2단계 인증 준비가 필요 없는
  **POP3를 기본 경로**로 삼고, 네이버·한메일·지메일은 기존 IMAP을 그대로 둡니다.
- **판독·적재·Firebase 등록은 IMAP과 완전히 같은 함수**를 씁니다(`Collector._handle_message`).
  프로토콜별로 다른 것은 "메일을 가져오는 방법"뿐입니다 — 판독기를 두 벌 만들지 않습니다.
- **서버 메일은 지우지 않습니다.** `dele()` 를 호출하는 코드가 없고, 테스트의 가짜 POP3는 DELE가
  불리면 예외를 던져 테스트를 실패시킵니다(회귀 방지 장치).
- 중복 방지는 `mailpilot/pop_uidl_cache.json`(계정별 UIDL 목록). UIDL 미지원 서버는 TOP으로 헤더만 받아
  Message-ID 해시로 대신합니다. 서버에서 사라진 UIDL은 캐시에서도 정리해 무한 증가를 막습니다.
- `collect_days` 는 POP3에서 메일 Date 헤더로 거릅니다. 오래된 메일은 본문(RETR)을 받지 않고
  캐시에만 기록해 다음 사이클에 다시 확인하지 않습니다.
