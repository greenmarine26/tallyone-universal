우리 회사 검수앱과 메일 수집기를 처음부터 끝까지 세우는 문서입니다.
**코드를 열 일은 없습니다.** 화면에서 값을 넣고 누르기만 하면 됩니다.

| | |
|---|---|
| 걸리는 시간 | 데이터베이스 만들기 15분 + 앱 설정 5분 + 수집기 10분 |
| 필요한 것 | 구글 계정 · 자료를 받는 회사 메일 계정 · 윈도우 PC 1대(수집기용) |
| 준비물 | 회사 로고 이미지(선택) · 회사 영문명·영문 주소(서류 머리글에 찍힙니다) |

> 그림 자리는 `[그림 N]` 으로 표시했습니다. 실제 화면 캡처는 설치할 때 붙입니다.

## 1부 — 데이터베이스(Firebase) 만들기 · 15분

검수 자료·선박·직원이 저장되는 **우리 회사 전용 데이터베이스**입니다.
구글이 무료로 주는 것(Spark 요금제)이며, 카드 등록 없이 시작합니다.
**여기서 만든 프로젝트는 우리 회사만 씁니다** — 다른 회사와 자료가 섞이지 않습니다.

아래 순서는 실제로 한 번 만들어 보며 적은 순서 그대로입니다. 순서를 바꾸지 마십시오.
(특히 **데이터베이스를 먼저 만들어야** 마지막에 복사할 설정에 `databaseURL` 이 들어갑니다.)

### 1-1. 프로젝트 만들기

1. <https://console.firebase.google.com> 접속 → 회사 구글 계정으로 로그인.
2. **[프로젝트 만들기]** → 이름은 알아보기 쉽게(예: `우리회사-tally`). 이름은 나중에 바뀌지 않습니다.
3. **Gemini(AI) 사용 제안 화면 → 끕니다.** 지금 필요 없습니다.
4. **Google 애널리틱스 → 끕니다(사용 안 함).** 켜면 계정 연결을 더 묻습니다.
5. [프로젝트 만들기] → 30초쯤 기다리면 완료 → **[계속]**.

[그림 1] 프로젝트 만들기 첫 화면 · 애널리틱스 끄기

### 1-2. 실시간 데이터베이스(Realtime Database) 만들기

1. 왼쪽 메뉴 **빌드 → Realtime Database** → **[데이터베이스 만들기]**.
2. 위치는 **싱가포르(asia-southeast1)** — 한국에서 가장 빠릅니다.
3. 보안 규칙은 **잠금 모드**로 시작 → [사용 설정].

> ⚠ **Firestore가 아니라 Realtime Database** 입니다. 이름이 비슷한 다른 제품이 옆에 있습니다.

[그림 2] Realtime Database 만들기 · 싱가포르 · 잠금 모드

### 1-3. 보안 규칙 게시

1. Realtime Database 화면 위쪽 **[규칙]** 탭.
2. 내용을 전부 지우고 아래를 붙여넣습니다.

```json
{
  "rules": {
    ".read": "auth != null",
    ".write": "auth != null"
  }
}
```

3. **[게시]**.

이렇게 하면 로그인하지 않은 외부인이 주소만으로 자료를 읽어 가지 못합니다.
(게시 뒤 콘솔이 "규칙이 안전하지 않습니다" 안내를 띄울 수 있습니다 — "인증만 되면 전부 접근"이라는 일반 안내이며, 이 판의 기준선입니다.)

[그림 3] 규칙 탭 · 붙여넣고 게시

### 1-4. 익명 인증 켜기

1. 왼쪽 메뉴 **빌드 → Authentication** → **[시작하기]**.
2. **로그인 방법** 탭 → 목록에서 **익명** → 사용 설정 → [저장].

앱과 수집기는 이 익명 인증으로 데이터베이스에 접속합니다. **켜지 않으면 앱이 자료를 읽지 못합니다.**

[그림 4] Authentication · 로그인 방법 · 익명 사용 설정

### 1-5. 웹앱 등록하고 설정 복사

1. 왼쪽 위 **톱니바퀴 → 프로젝트 설정**.
2. 아래 **내 앱** 에서 **웹(`</>`)** 아이콘 클릭.
3. 앱 닉네임(예: `우리회사 TallyOne`) 입력 → **호스팅은 체크하지 않습니다** → [앱 등록].
4. 화면에 나오는 `firebaseConfig` 블록을 **통째로 복사**합니다.

```js
const firebaseConfig = {
  apiKey: "AIza....",
  authDomain: "우리회사-tally.firebaseapp.com",
  databaseURL: "https://우리회사-tally-default-rtdb.asia-southeast1.firebasedatabase.app",
  projectId: "우리회사-tally",
  storageBucket: "우리회사-tally.firebasestorage.app",
  messagingSenderId: "000000000000",
  appId: "1:000000000000:web:xxxxxxxx"
};
```

> **`databaseURL` 줄이 보이지 않으면** 1-2를 건너뛴 것입니다. 데이터베이스를 만든 뒤 이 화면을 새로고침하십시오.

이 블록은 **앱과 수집기 양쪽에 같은 것**을 넣습니다. 메모장에 붙여 두십시오.
(이 값은 비밀번호가 아닙니다. 공개돼도 1-3의 규칙이 막습니다.)

[그림 5] 프로젝트 설정 · 웹앱 등록 · firebaseConfig 복사

## 2부 — 앱 첫 실행 마법사 3단계

앱 주소를 **크롬(안드로이드) 또는 사파리(아이폰)** 로 엽니다.
설정이 없는 기기에서는 로그인 화면 대신 **[첫 실행 설정]** 화면이 먼저 뜹니다.

[그림 6] 첫 실행 설정 · 1단계 화면

### 2-1. 1단계 — 데이터베이스

1-5에서 복사한 `firebaseConfig` 를 큰 칸에 **그대로 붙여넣습니다.**
`const firebaseConfig = { ... };` 형태 그대로도 되고, 중괄호 안만 붙여넣어도 읽습니다.
아래에 **"✓ 읽었습니다"** 와 항목 목록이 나오면 성공입니다. → **[다음 — 회사 정보]**

- 붉은 글씨로 "필수 항목을 찾지 못했습니다"가 나오면 복사가 잘린 것입니다. 다시 통째로 복사하십시오.
- 이 단계에서 앱은 **그 데이터베이스에 이미 회사 설정이 있는지 먼저 확인**합니다.
  있으면 2·3단계 대신 [4부](#4부--두-번째-기기--다른-검수원-휴대폰) 화면이 나옵니다.

### 2-2. 2단계 — 회사 정보

| 칸 | 설명 | 예 |
|---|---|---|
| 회사명 (한글) * | 화면 곳곳에 나오는 이름 | 그린마린 |
| 회사명 (영문) | **서류 머리글**에 찍힙니다 | GREEN MARINE CO., LTD. |
| 주소 (영문) | 서류 머리글 둘째 줄 | PYEONGTAEK, KOREA |
| 모항 코드 * | UN/LOCODE 5자 — 우리 항구 | KRPTK |
| 모항 이름 * | 사람이 부르는 이름 | 평택 |
| **터미널 (쉼표로 구분) \*** | **우리가 검수하는 부두·터미널.** 쉼표로 나눠 적습니다 | `PCTC, PNCT` / `선광, ICT, 한진` |
| 앱 이름 | 화면 위쪽·브라우저 제목 | TallyOne |
| 회사 로고 | 이미지 선택(512px로 자동 축소) | (선택) |

- **모항 코드**는 앱이 "우리 항 화물"만 세는 기준입니다. 잘못 넣으면 통과 화물까지 세어 숫자가 틀립니다.
- **터미널**은 PORT-MIS 화면의 부두별 집계 칩에 그대로 나옵니다. 칸 아래에 `2곳: PCTC · PNCT` 처럼
  읽어들인 결과가 바로 보이니 확인하고 넘어가십시오. 한 곳 이상 있어야 [다음]이 열립니다.
  (부두 번호대는 이 판에서 받지 않습니다 — 이름만 등록됩니다.)

[그림 7] 2단계 · 터미널 입력칸과 읽어들인 결과

### 2-3. 3단계 — 최초 관리자

앱의 **소유자**가 될 사람입니다. 권한을 회수할 수 없고, 직원 명단·매트릭스 권한을 관리합니다.
나머지 직원은 이 사람이 앱 안에서 추가합니다.

- 이름 * : 한글/영문 2~10자
- 직책 : 기본 `수석검수사` (자유 입력 — 무엇을 넣든 소유자는 수석 화면에 들어갑니다)

**[설정 마치고 시작]** → 앱이 데이터베이스에 첫 자료(`settings`·`staffList`)를 심고 새로고침합니다.
로그인 화면이 뜨고 이름을 넣으면 **"선택됨: 이름 · 직책"** 이 보여야 정상입니다.

[그림 8] 3단계 · 완료 후 로그인 화면

> 💡 **휴대폰 홈 화면에 추가**해 두면 앱처럼 전체 화면으로 열립니다.
> 크롬: 메뉴 → 홈 화면에 추가 / 사파리: 공유 → 홈 화면에 추가.

## 3부 — 메일 수집기(MailPilot) 설치

선사에서 오는 메일(베이플랜·적하목록·EDI)을 **선박·항차 폴더로 자동 정리**하고,
앱의 **선박 목록을 스스로 채워 주는** 프로그램입니다. 윈도우 PC 한 대에 설치해 켜 둡니다.

> ⚠ **개인 PC 전용.** 설정 파일에 메일 비밀번호가 평문으로 저장됩니다(0.1판의 한계). 공용 PC 금지.

### 3-1. 파이썬 설치 (한 번만)

1. <https://www.python.org/downloads/> → [Download Python] (3.9 이상).
2. 설치 첫 화면의 **“Add python.exe to PATH” 를 반드시 체크**하고 설치.

[그림 9] 파이썬 설치 · PATH 체크

### 3-2. 수집기 실행

저장소의 `mailpilot` 폴더를 PC에 내려받고 **`run_mailpilot.bat` 을 더블클릭**합니다. 설정 창이 뜹니다.
(파이썬을 못 찾으면 검은 창에 설치 안내가 나옵니다 — 3-1을 다시 하십시오.)

[그림 10] 수집기 설정 창

### 3-3. 메일 계정 — 메일사별 준비

먼저 **쓰는 메일사에서 IMAP을 켜야** 합니다. 이걸 안 하면 아이디·비밀번호가 맞아도 접속이 거부됩니다.

#### 네이버 메일
1. 네이버 메일 → **환경설정** → **POP3/IMAP 설정** → **IMAP/SMTP 사용** 을 **“사용함”** → 저장.
2. **2단계 인증을 쓰는 계정**이면 로그인 비밀번호로는 접속되지 않습니다.
   네이버 → **내정보 → 보안 설정 → 애플리케이션 비밀번호** 에서 새 비밀번호를 발급받아
   수집기의 비밀번호 칸에 **그 값**을 넣습니다.

#### 한메일(다음)
1. 다음 메일 → **환경설정** → **IMAP/POP3** → **IMAP 사용** 켜기.
2. 카카오 2단계 인증을 쓰면 앱 비밀번호가 필요합니다.

#### 지메일
1. **앱 비밀번호가 반드시 필요합니다.** 일반 로그인 비밀번호로는 IMAP이 막혀 있습니다.
2. 구글 계정 → **보안** → **2단계 인증** 을 먼저 켜고 → **앱 비밀번호** 발급 → 그 값을 넣습니다.

#### 직접 입력(회사 메일·그룹웨어)
메일 관리자에게 **IMAP 서버 주소와 포트**(보통 993 / SSL)를 받아 넣습니다.

[그림 11] 네이버 IMAP 설정 · 앱 비밀번호 발급

### 3-4. 수집기 설정 채우기

| 칸 | 넣을 것 |
|---|---|
| 메일사 | 네이버 / 한메일(다음) / 지메일 / 직접 입력 — 고르면 서버·포트가 자동으로 채워집니다 |
| 이메일 · 비밀번호 | 자료 메일을 받는 계정 (2단계 인증이면 **앱 비밀번호**) |
| 메일박스 폴더 | 첨부를 쌓을 폴더. 구글 드라이브 폴더를 쓰면 다른 PC에서도 봅니다 (예: `G:\내 드라이브\MAILBOX`) |
| 최근 며칠 / 주기 | 기본 7일치를 10분마다 |
| firebaseConfig | **1-5에서 복사한 것과 똑같은 값** — 큰 칸에 그대로 붙여넣기 |

**[연결 테스트]** → 메일·데이터베이스 둘 다 OK 인지 확인 → **[저장]** → **[수집 시작]**.

[그림 12] 연결 테스트 통과 화면

### 3-5. 무엇이 어디에 쌓이나

```
{메일박스 폴더}/
  SWDN/2608S/SWDN_2608S_ACTUAL_BAPLIE.edi     ← 선박코드 / 항차 / 첨부
  ATPR/2625E/ATPR 2625E CNTR LIST.xlsx
  _미분류/20260804_연태훼리 2706W CLL 3차/...    ← 판독 실패도 절대 버리지 않습니다
```

- 받는 첨부: `.edi .asc .txt .xls .xlsx .pdf` · 같은 파일은 다시 받지 않습니다.
- 로그: `mailpilot/logs/YYYYMMDD.txt` (한국어)
- 수집기가 선박을 발견하면 앱의 선박 목록에 자동으로 올라옵니다. **선박을 미리 등록할 필요가 없습니다.**
- 자세한 규칙·한계는 [수집기 문서](../mailpilot/README.md)를 보십시오.

## 4부 — 두 번째 기기 · 다른 검수원 휴대폰

**회사 정보를 다시 입력하지 않습니다.** 기기마다 값이 어긋나면 서류가 달라집니다.

1. 그 기기에서 앱 주소를 엽니다 → 첫 실행 설정 1단계.
2. **같은 `firebaseConfig`** 를 붙여넣고 [다음].
3. 앱이 데이터베이스를 확인해 **“기존 회사 설정을 찾았습니다 — {회사명}”** 을 보여 줍니다
   (모항·앱 이름·소유자·로고 미리보기).
4. **[불러오고 시작]** → 끝. 회사 정보·터미널·로고가 그대로 따라옵니다.
   직원 명단도 건드리지 않습니다.

[그림 13] 기존 회사 설정을 찾았습니다 화면

> `firebaseConfig` 는 사내 메신저로 그대로 전달해도 됩니다(1-3 규칙이 외부 접근을 막습니다).
> [새로 설정] 은 **회사를 새로 만들 때만** 누르십시오 — 기존 설정을 덮어씁니다.

## 5부 — 문제 해결

### ① 로그인 화면에서 이름을 넣어도 들어가지지 않는다
- 최초 관리자(2-3)에서 넣은 이름과 **한 글자라도 다르면** 안 됩니다(띄어쓰기 포함).
- 다른 검수원은 **소유자가 앱 안에서 추가**해야 목록에 생깁니다.
- 소유자 본인인데 수석 화면이 잠겼다면 새로고침 한 번 — 그래도 안 되면 ③을 보십시오.

### ② 수집기를 돌렸는데 0건이다
- 메일사에서 **IMAP을 켰는지**(3-3) 먼저 확인.
- 2단계 인증 계정인데 로그인 비밀번호를 넣지 않았는지 — **앱 비밀번호**여야 합니다.
- "최근 며칠"이 너무 짧지 않은지(기본 7일). 오래된 메일은 범위 밖입니다.
- 로그 `mailpilot/logs/오늘날짜.txt` 에 한국어로 사유가 남습니다.
- 메일은 읽었는데 파일이 안 보이면 **`_미분류` 폴더**를 보십시오 — 선박명·항차를 못 읽은 자료가 거기 있습니다(버리지 않습니다).

### ③ Permission denied · 자료가 안 보인다
거의 언제나 1부의 두 가지 중 하나입니다.
- **익명 인증(1-4)이 꺼져 있다** → Authentication → 로그인 방법 → 익명 → 사용 설정.
- **규칙(1-3)을 게시하지 않았다** → 규칙 탭에 `auth != null` 두 줄이 있는지, [게시]를 눌렀는지.
- 수집기 쪽이면 `firebaseConfig` 의 `databaseURL` 이 앱과 같은 값인지 확인하십시오.

### ④ 첫 실행 마법사를 다시 하고 싶다 (설정을 잘못 넣었다)
설정은 그 브라우저에 저장돼 있습니다. **저장된 두 값을 지우면** 마법사가 다시 뜹니다.

- **PC 크롬**: `F12`(개발자도구) → **Application** 탭 → 왼쪽 **Local Storage** → 앱 주소 선택 →
  `gm_fb_cfg_v1` 과 `gm_tenant_cfg_v1` 두 줄을 지우고 새로고침.
- **휴대폰**: 브라우저 설정 → 사이트 설정/저장된 데이터 → 앱 주소의 **데이터 삭제** → 다시 접속.
- 회사 정보만 고치려면 마법사를 다시 돌리지 말고 **1단계까지만 진행 → [새로 설정]** 으로 갱신하십시오.
- **데이터베이스의 자료는 지워지지 않습니다** — 지워지는 것은 그 기기의 설정뿐입니다.

### ⑤ `_미분류` 폴더에 자꾸 쌓인다
수집기가 선박명이나 항차를 못 읽은 경우입니다. 자료는 그대로 있으니 손으로 선박/항차 폴더에 옮기면 됩니다.
- 한글 선박명(예: "연태훼리")은 아직 못 읽습니다.
- 선박명이 세 낱말이면 뒤 두 낱말만 씁니다(`XIN TAI PING` → `TAI PING`).
- 제목·첨부 어디에도 항차 표기가 없으면 판독할 근거가 없습니다.
